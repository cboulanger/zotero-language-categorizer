# Classification progress popup — Design

Date: 2026-10-02

## Purpose

For large libraries, the classify dialog's per-row status column isn't
enough feedback: with hundreds or thousands of rows in a virtualized table,
a user can't tell classification is actually progressing unless the
currently-scrolled rows happen to be the ones updating. Add a native Zotero
progress popup, visible independent of dialog scroll position, showing an
aggregate "x/y items processed" count and a progress bar.

## Scope

- Covers the **classify phase only** (`DialogController.classify()` in
  `src/modules/dialog/classify-dialog.ts`) — the slow, silent part for large
  libraries, since it runs immediately on dialog open with no prior user
  feedback.
- Does **not** cover `runApply()` (the Apply/save phase). Saving via
  `item.saveTx()` is comparatively fast and already has its own per-row
  visual feedback (the Status column's check/cross).
- The popup always appears, every time `classify()` runs, regardless of row
  count. No row-count threshold — for small batches it appears briefly and
  auto-closes; this avoids introducing a magic-number special case for
  "large" vs. "small".

## Implementation

Use `ProgressWindowHelper` from `zotero-plugin-toolkit` (already a project
dependency, already used for `VirtualizedTableHelper` in the same file) —
not the raw `Zotero.ProgressWindow` API — for consistency with the rest of
the codebase's toolkit usage.

In `classify()`:

- On entry, before the chunk loop: create the popup with one line, text
  showing `0/<total>` and `progress: 0`, then `.show(-1)` — the `-1`
  disables `ProgressWindowHelper`'s default 5-second auto-close timer, since
  classification can run longer than that for large libraries and the popup
  must stay open and updating throughout.
- After each chunk inside the existing `chunk(this.rows, CHUNK_SIZE)` loop
  (already yields every 50 rows via `await new Promise(r => setTimeout(r,
  0))` for UI responsiveness — reusing that existing cadence for progress
  updates, no restructuring of the loop): call `.changeLine({ text, progress
  })` with the running total processed and `Math.round((processed / total) *
  100)`.
- In the existing `finally` block (alongside `actionButton.disabled =
  false`): call `.startCloseTimer(2000)` so the popup auto-dismisses 2
  seconds after classification finishes, rather than lingering indefinitely
  (since `-1` disabled the default auto-close).

No new module — this is entirely inside the existing `classify()` method.
`this.rows.length` is always `> 0` when `classify()` runs (the empty-state
early return in `init()` prevents the table/classify path from running
otherwise), so no divide-by-zero guard is needed for the percentage
calculation.

## Localization

Two new Fluent keys, added to all four existing locale files
(`addon/locale/{en-US,de,fr,es}/addon.ftl`), matching this project's
existing tone and the pattern already used for interpolated messages
(`src/utils/locale.ts`'s `getString(id, { args })`):

```ftl
progress-classify-headline = Classifying item languages…
progress-items-processed = { $current }/{ $total } items processed
```

German, French, and Spanish equivalents are written in the same register as
the existing `dialog-*` strings in each locale file.

`typings/i10n.d.ts` is scaffold-generated from the `.ftl` files (per its
"Generated by zotero-plugin-scaffold" header) — the implementation plan
regenerates it rather than hand-editing the two new keys in.

## Error handling

None needed beyond what already exists: the chunk loop's existing `finally`
block already guarantees `actionButton.disabled = false` runs even if
`previewRows` throws for a row (it doesn't — `previewRows` already catches
per-row classifier errors internally); the same `finally` block is extended
to also start the popup's close timer, so the popup is cleaned up on every
exit path from `classify()`.

## Testing

Like the rest of `DialogController`, this touches the live `Zotero` global
(`ProgressWindowHelper` wraps `Zotero.ProgressWindow`) and isn't
unit-testable in isolation — consistent with how `classify-dialog.test.ts`
already only covers the pure helper functions (`buildRows`, `previewRows`,
`formatCreators`) and leaves `DialogController` itself to manual
verification. Manual check: open the classify dialog on a collection with
enough items to span multiple 50-row chunks, confirm the popup appears
immediately, the counter and bar advance chunk-by-chunk, and it auto-closes
~2 seconds after the last chunk completes.

## Out of scope

- Progress feedback for the Apply/save phase (`runApply()`).
- A row-count threshold below which the popup is suppressed.
- Per-item (vs. per-chunk) progress granularity.
