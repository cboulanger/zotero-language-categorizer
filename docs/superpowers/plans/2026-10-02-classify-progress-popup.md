# Classification Progress Popup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show a native Zotero progress popup during the classify dialog's classification phase, with an "x/y items processed" counter and progress bar, so users with large libraries can see classification is actually running.

**Architecture:** Entirely inside `DialogController.classify()` in `src/modules/dialog/classify-dialog.ts`. Use `ProgressWindowHelper` from `zotero-plugin-toolkit` (already a dependency, already used in this file for `VirtualizedTableHelper`). Create the popup before the existing chunk loop, update it once per chunk (reusing the loop's existing per-chunk yield point — no new scheduling), start its close timer in the existing `finally` block.

**Tech Stack:** TypeScript, `zotero-plugin-toolkit`'s `ProgressWindowHelper`, Fluent (`.ftl`) localization via `src/utils/locale.ts`'s `getString()`.

## Global Constraints

- Scope is the classify phase only (`classify()`); `runApply()` is untouched — copied verbatim from the spec's Scope section.
- The popup always appears, every run, regardless of row count — no row-count threshold.
- New Fluent keys must be added to **all four** locale files: `addon/locale/{en-US,de,fr,es}/addon.ftl`.
- `typings/i10n.d.ts` is a generated file (header: "Generated by zotero-plugin-scaffold") — normally regenerated by `npm run build`. That build currently fails in this sandbox (pre-existing `@swc/core` native-binding permissions issue, unrelated to this feature — see conversation history). Hand-edit the two new entries into the existing sorted list instead, matching its exact format.
- Reference spec: `docs/superpowers/specs/2026-10-02-classify-progress-popup-design.md`.

- [x] **Step 2: Rewrite `classify()` to create, update, and close the popup**

Replace the entire method body shown above with:

```ts
async classify(actionButton: HTMLButtonElement): Promise<void> {
  const total = this.rows.length;
  const progress = new ProgressWindowHelper(
    getString("progress-classify-headline"),
  )
    .createLine({
      text: getString("progress-items-processed", {
        args: { current: 0, total },
      }),
      progress: 0,
    })
    .show(-1);
  try {
    const classifier = getClassifier();
    let processed = 0;
    for (const group of chunk(this.rows, CHUNK_SIZE)) {
      previewRows(group, classifier);
      processed += group.length;
      progress.changeLine({
        text: getString("progress-items-processed", {
          args: { current: processed, total },
        }),
        progress: Math.round((processed / total) * 100),
      });
      this.table?.treeInstance.invalidate();
      await new Promise((r) => this.win.setTimeout(r, 0));
    }
  } finally {
    actionButton.disabled = false;
    progress.startCloseTimer(2000);
  }
}
```

Note: `total` is `this.rows.length`, always `> 0` here — `init()`'s empty-state early return (`if (this.rows.length === 0) { ...; return; }`) means `classify()` is never invoked with zero rows, so no divide-by-zero guard is needed in the percentage calculation.
